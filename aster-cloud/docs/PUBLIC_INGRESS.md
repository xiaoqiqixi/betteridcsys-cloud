# 浮动公网 IP：地址关联与实例公网入站规则

## 结论与参考

浮动/弹性公网 IP 是独立资源，分配、绑定、解绑和回收是资源生命周期；通过公网
地址到实例私网地址的整地址 NAT 提供连接，并不要求将公网地址写进 guest。这条
执行链保留，不重写成共享 NAT 端口转发，也不照搬参考产品的 API。

但**绑定地址不等于允许访问全部服务**。阿里云把 EIP 关联和实例安全组规则分开；
魔方云将弹性 IP 作为可关联实例的资源，业务/财务侧则将 IP 产品与云产品关联。
本项目据此将地址库存、实例关联、访问策略与财务账务分层，不用一个风险勾选冒充防火墙。

## 本轮产品模型

1. **公网 IP 资源**负责库存、客户归属、占用和回收；不因绑定按钮默认创建放行规则。
2. **实例关联**负责精确 IP → 同客户、同 VPC 目标。切换目标时取得新实例的规则，
   旧实例开放的端口不会跟着 IP 搬走。解绑保留独立 IP，不同时回收资源。
3. **实例公网入站规则**单独配置来源 IPv4 CIDR、协议及目标端口；无规则时拒绝未经
   允许的公网新入站。TCP/UDP 支持明确端口区间，ICMP 规则仅允许 echo；相关 ICMP
   错误仅限 3/11/12 且有真实 conntrack 关联，不开放 redirect 或任意 IP 协议。
4. 合法主动出站的回包仍可通过；出站、管理网、metadata、underlay、保留网段和
   anti-spoof 继续由原独立 root 批准和节点规则限制，新 allow 规则不能覆盖这些底线。
5. 财务产品只描述销售/归属与资源合同，不充当网络放行规则。本轮不修改金额、币种、
   支付、幂等或财务历史快照，也未新增财务自动分配公网资源的产品策略。

## 范围不是完整安全组

当前实现是**VPC 实例经浮动 IPv4 的公网入口过滤**，策略归属实例。它不是完整
VPC 安全组，不控制东西向流量、IPv6、普通 Linux Bridge 真直绑或其它独立共享 NAT
地址入口，也不取代 guest 防火墙。UI 对未支持的网络类型明确说明，不显示假保护。

独立共享 NAT 即使向同一个私网实例转发，也不会借其端口白名单绕过被拒绝的浮动 IP；
反过来，浮动 IP 规则也不悄悄改写该独立 NAT 地址原有授权。执行器检查原 conntrack
公网目的地址，并在浮动入站链终止拒绝，避免规则链 fallthrough 混用。

## 默认与历史兼容

- 新绑定始终冻结非空 `floating_ips[].ingress` 对象。默认 revision0、`rules:[]` 表示
  **拒绝未经允许的新入站**，不表示全开放，也不表示未配置可忽略。
- 旧快照省略 ingress 的含义保持原 legacy 整地址转发，历史字节、请求摘要和回执不改。
  读取时明确显示“旧映射未受平台入站规则保护”；不会突然标记成安全，也不会静默
  断开既有服务。管理员须显式配置规则，经过新 epoch 升级该入口。
- `ingress:null`、空摘要、错客户/实例、重复字段、无效端口、非规范 CIDR 或规则损坏
  均拒绝，不能用 null 降级回 legacy。
- 普通网络规划/恢复不允许外部提交 floating 列表绕过策略。原策略作为不可变意图
  保留；未知状态只允许原任务核对或显式完整安全解绑恢复，不能换 key 扩权。

## 持久化、版本与确认

主控 schema **10** 追加实例策略版本和固定操作结果，不修改001–009已发布SQL。
每次策略编辑都带 `expected_revision`；规则ID稳定、排序和完整SHA绑定实例、客户、
版本与规则。策略属于实例，不属于待移动的公网 IP。

绑定中修改策略会在同一 `controller_lock` 事务中写入新策略版本、新完整 epoch、
不可变绑定意图和审计，并递增公网资源 `binding_generation`，防止旧绑定草稿覆盖新规则。
202只是接纳；只有所有节点 prepare → program → release 精确回执完成才显示生效版本。
读取已绑定入口时还要求所有参与节点的新鲜能力、当前root profile pins及当前网关/NAT
授权仍匹配。心跳过期、能力撤回、profile变更或撤销浮动IP授权均显示待核实，生效版本
置空；不拿历史回执冒充当前就绪。已保存的期望版本与原操作ACK不改，须经显式网络
任务重新确认。该读取不会自动修改节点规则，也不声称提供实时流量健康探测。
未绑定时只保存供将来使用的规则，不宣称当前流量已受到节点过滤。

规则收紧经过原隔离屏障、实际 nft 规则替换、专用 conntrack 撤销和严格读回；
不能只删UI列表而保留旧长连接。返回未知时保存原完整意图，仅读取原操作，绝不静默重发。

所有参与节点须有新鲜、当前 profile、非维护的 `floating-public-ingress/1` 能力公告。
旧 binary 不被猜为支持：缺能力时在规划和最后派发前安全拒绝，不能为兼容回退成全放行。
升级须先备份独立主控库与节点 journals、停写并升级全部相关节点，再显式启用新策略。
数据库 schema10 回滚须恢复配套一致备份，不能删版本表或清空 unknown 状态。

## API

| 接口 | 用途 |
| --- | --- |
| `GET /console/v1/instances/{id}/public-ingress` | 当前期望/已确认版本、支持情况和旧映射状态 |
| `POST` 同路径 | `{expected_revision,rules}`；初次202、固定结果重放200 |
| `GET /console/v1/public-ingress-operations/{id}` | 仅当前actor原策略操作的不可变请求与结果 |

读取要求 `nodes.read + instances.read`；写入还需 `nodes.manage + instances.manage`，
保留同源HTTPS/CSRF/Origin。绑定新增 `expected_ingress_revision`：UI选定目标时固定
其版本，不能发送时偷偷切到新策略。旧请求缺省仅能新绑定revision0默认拒绝；若目标
已有非零版本则要求显式确认并匹配。已存在旧key仍按原body重放，不覆盖历史ACK。
