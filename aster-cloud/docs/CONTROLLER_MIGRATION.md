# 主控维护与迁移

主控搬家是将管理服务迁到另一台服务器，不是移动客户虚拟机。实例、节点、任务和财务资源引用应保持不变；运行中的虚拟机不因主控维护而关闭。

## 使用前确认

完整的加密备份、空目标恢复、接管和后台向导尚未开放。不要手工复制运行库到另一台主控后同时启动两边。现有 `0.1.0-rc.1` 下载包也不包含下述新维护接口。

新源码中的源端维护工具只支持由原生安装器管理的 Ubuntu 22.04 / 24.04 amd64 主控。本地持久文件系统、cgroup v2、固定配置和原始 systemd 单元均需通过检查。自定义单元、额外覆盖配置、旧版本、损坏的记录或文件身份变化会拒绝操作，不会覆盖它们。

## 源端维护流程

安装包在不可变版本目录下提供 `templates/host-management/controller-migration.py`，与主控二进制一起记录在包清单中。使用 root 和系统 Python 3 执行该工具，不另行下载脚本混用不同版本。

| 操作 | 用途 |
| --- | --- |
| `capabilities` | 查询工具能力；不读取密钥、不连接数据库 |
| `plan` | 只读核对安装来源记录、配置和受管理的服务/心跳单元 |
| `isolate --operation <ID>` | 停止新请求接纳、排空本机进程、持久屏蔽并停止已核对的单元 |
| `status --operation <原 ID>` | 重新核对屏蔽、进程和记录，报告实际阶段 |
| `resume-source --operation <原 ID>` | 仅在未开始导出时恢复原单元并解除停写；不自动启动服务 |

ID 为新生成的 32 位小写十六进制值。同一维护过程必须一直使用同一个 ID；超时后先查状态，不要换 ID 重做。记录、原始单元和撤销历史会保留。工具不会删除客户资源、修改财务数据库、支付状态或历史快照。

“源端已隔离”仅指本机受管理的新版本主控和已批准的心跳启动源，**不等于迁移完成**。工具不能证明另一台主机或管理员自行启动的旧程序已经停用。源机重启、并发在途任务、跨主机接管仍须按完整验收流程验证；不可仅凭一份状态 JSON 启动目标写入。

若导出已开始，工具拒绝本地解除隔离；必须先解决目标接管状态，不能两边同时运行。工具不会提供忽略校验、强制覆盖、任意路径或 shell 参数。
