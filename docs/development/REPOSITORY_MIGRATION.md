## 删除旧仓库前必须完成

1. **来源和备份**：保存原 Git bundle、标签与 Release 元数据、资产摘要及必要安装恢复材料，核对数量和哈希。私有凭据与数据库不进入公开仓库。
2. **新仓库构建**：各自 main 的实际构建成功；后端与主控 Ubuntu22/24；前端类型/测试/构建/格式/依赖检查。不能拿原仓库 CI 代替。
3. **前后端组合**：固定前端资产摘要及对应提交；真实 MySQL、同源 HTTPS、客户和管理员浏览器回归；钱款、支付幂等、多币种、历史快照不变。
4. **发行来源迁移**：后端更新器和主控安装器绑定新仓库 ID、工作流、源码与签名；没有旧新 SHA 白名单、任意仓库参数或禁用校验。
5. **首版 Release**：三个仓库独立首版发布，检查构建来源、完整资产、匿名下载、SHA256和适用签名；主控保持真实 KVM 未验的预发布标志。
6. **原生与旧实例**：安装、systemd/Nginx/TLS、升级、备份恢复和回滚，及已有实例从旧来源向新来源的受控迁移。不能用复制附件或本地打包代替。
7. **删除前复核**：新仓库安装/更新/文档不存在必须访问原仓库才能工作的依赖；确认本轮全部门禁通过后，才执行用户已授权的原仓库及 Releases 删除。
