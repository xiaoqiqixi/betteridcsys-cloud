# 主控迁移的节点材料连续性

本合同属于 M03，不是完整主控迁移已可用的声明。

## 必须保留的身份

现有 `NodeProfile.Digest()` 包含 CA、客户端证书和私钥的路径。迁移时直接把这些字段改成目标路径，会让已保存的节点批准摘要、任务和迁移记录失配；不能重写历史行来掩盖这个差异。

在 root 管理的主控配置中新增可选 `node_materials`：每项绑定节点 ID、原 profile SHA256，以及三个实际文件路径和各自的 SHA256。节点原有端点、地址白名单、服务端指纹和 profile 字段不变。没有该字段的配置保持原行为；这个能力不是证书轮换或修改节点身份的授权。

配置解析拒绝未知节点、重复映射、过期 profile 摘要、非法路径或摘要。实际连接前依旧核查文件所有者、权限、硬链接/符号链接、内容摘要、TLS CA、客户端密钥配对、服务端指纹及批准地址。映射已存在时不回退到旧路径；缺失、变更或权限不符都必须拒绝。进程内部的路径解析结果不能进入 JSON 或 `NodeProfile.Digest()`。

## 导出与恢复

源端导出必须读取真实生效的材料位置，并在加密索引中保留引用及摘要；不能只让连接读取新路径，而备份仍误读旧路径。离线源验证复核映射与材料摘要，支持再次迁移。新目标最终将材料放在自己管理的固定目录，不能依源包路径写入任意宿主位置；此写入与配置发布需后续目标协调器的不可变计划和封存状态批准。

材料位置连续性不代表目标有权接管节点。旧 Web 会话撤销、目标配置发布、源端退役/节点单活、地址变更和重启恢复仍由后续迁移阶段分别确认。金额、支付及财务历史快照不受影响。

## 验收界面

- 使用已约定的配置解析和真实 mTLS 连接界面，不 mock 证书加载或 TLS 握手。
- 原材料路径不存在时，已批准映射仍可完成双向认证；节点 JSON/profile 摘要保持原值。
- 文件缺失/替换、错误摘要、错误服务端指纹、同 CA 未批准客户端、符号链接/硬链接和权限漂移均失败；不尝试旧路径或重发资源请求。
- 真实源导出、离线验证、目标材料发布及再次导出需要各自回归；不能用配置单测代替这些闭环。

## 本批实现与验收范围

配置解析、实际节点连接、任务候选选择、源端隔离材料摘要、加密导出及离线源验证已经使用同一组生效位置；原 profile JSON、摘要和既有无映射配置的编码不变。真实 mTLS 回归覆盖原路径不存在的成功路径、原路径仍可用时禁止回退、三个内容摘要、文件替换/丢失/权限/链接，以及 CA、客户端身份、服务端指纹和批准地址拒绝。

本地 `go test -race ./...`、`go vet ./...`、Linux amd64 四个程序编译、实际离线验证 CLI、安装与发布合同检查通过。本地没有本轮隔离 MySQL，不据此宣称原生恢复或完整迁移通过。Ubuntu22/24 实库源主机夹具增加了“历史路径不存在、实际映射导出成功、有效 PEM 字节变化明确拒绝”的断言；须以本提交的 CI 为准。

目标材料尚未由安装器自动落盘或发布为运行配置；会话撤销、源退役/节点接管及迁移后台也未由本批完成。运行时支持不是可供用户手工绕过封存的激活入口。
