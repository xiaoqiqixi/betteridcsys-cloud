# 统一安装与主控迁移实施合同

## 产品流程

统一入口只要求运行一条命令，然后明确选择：`1 安装云主控`、`2 安装 KVM 被控`、`0 退出`。主控、节点仍是两个隔离部署角色，不因统一入口而默认混装。缺少选择、空输入、无交互终端、下载失败和验签失败均不能默认安装。

自动化使用同一入口的显式 `controller` / `node` 参数；不得接受自定义下载 URL、shell、忽略校验、自动同意安装或自动开放网络参数。依赖准备、专用数据库、libvirt、配置、安装和启动仍分别要求实际向导确认。用户不下载源码、不安装编译器。

支持范围保持 Ubuntu22.04/24.04 amd64。新入口先核验不可变已发布 bootstrap 的精确大小/SHA256，再委托现有签名验证和生产安装器。新仓库正式发行前仍引用旧 0.1.0-rc.1，不能把入口合并写成新发行完成；原仓库继续保留。真实 tty 的四组合下载/验签/plan 通过后，README 才切换为新入口的固定提交 URL。

## 从参考产品取什么，不取什么

参考[魔方云安装说明](https://docs.idcsmart.com/docs/魔方云/1.%20环境部署/1.1安装魔方云KVM加强版)的统一安装入口与角色选择；参考[主控迁移教程](https://docs.idcsmart.com/docs/魔方云/8.%20关于迁移/魔方云主控迁移教程（推荐）)的“备份 → 新主机安装 → 恢复 → 登录 → 节点重连”流程。只参考产品思路，不调用其 API，不复制实现，不引入其授权机制，也不照搬关闭 SELinux、清空信任或广泛开放端口的步骤。

这里把两件事明确分开：

- **主控搬家**：同一个控制平面更换管理服务器，保留 controller ID、实例/节点 ID、操作 ID、审计和财务资源引用；不搬客户虚拟磁盘、不关闭客户 VM。
- **跨主控迁移实例**：两个独立控制平面间移交选定实例，需要短时一次性配对、双方授权、资源映射与所有权切换；参考[跨主控迁移](https://docs.idcsmart.com/docs/魔方云/8.%20关于迁移/跨主控迁移)。这不是数据库整库恢复，也不能复用同一 controller ID 冒充独立平台。

下列是尚待实现的完整迁移合同，不是当前可用功能说明。已有四阶段 VM 冷迁移不能证明主控搬家已经完成。

## 主控搬家的完整闭环

### 1. 预检查与停写

- 检查发行来源、程序版本、schema、剩余空间、目标系统、独立数据库及回退材料。
- 冻结新增资源/身份写入与财务开通接纳；明确维护响应，不把付款或财务订单改为失败。
- 停止主控自动网络执行器和心跳调度，等待已受理任务稳定。未知结果保留原 ID 和状态，禁止重发、清除或自动当成功；不冻结运行中的 VM。
- 源主控服务和定时器停止并持久隔离，产生主机私有迁出回执。目标接管前不解除。仅靠网页 maintenance 标志不能证明源已隔离。

### 2. 可恢复迁移包

- 一致性备份独立主控库：迁移记录、身份/角色/授权修订、审计、任务及不确定状态、实例、网络/IP/NAT/浮动 IP 绑定和占用、配置版本。
- 备份受保护配置、控制身份与节点 mTLS 客户端证书/私钥、CA、固定节点指纹、批准的 presets/overlay/fabric 映射、发行/安装/操作回执。文件引用必须全部解析和审计，拒绝链接、越界、缺失和共享可写路径。
- 迁移包加密并认证，密钥通过独立安全渠道交付；清单绑定 controller ID、操作 ID、程序/schema/协议版本、每个文件的大小/摘要和总量。不把单独 SHA256 或包自带 manifest 当来源认证。
- 不包含财务数据库、客户 VM 磁盘、任意宿主目录或无关 SSH 凭据。下载/导出有审计与过期控制，不在日志和 HTTP 错误中泄漏密钥、DSN 或路径。

### 3. 新主机恢复

- 使用统一入口安装同一受支持版本的主控软件，进入**未激活恢复模式**；不能先创建一个已运行的新控制平面再覆盖它。
- 验证迁移包、源隔离回执、版本兼容、目标控制面为空及空间。目标数据库必须新建且独立；禁止覆盖现有业务库。
- 恢复原 controller ID、资源/操作/财务引用和审批约束。迁移配置只允许明确目标路径、监听/TLS/DNS变更，不能静默替换节点端点或资源映射；profile SHA 改变必须另做受控兼容迁移。
- 保留用户账户与密码哈希，撤销旧 Web 会话并要求重新登录。节点 mTLS 控制身份与 Web 会话是两套边界，不能通过清空指纹或复制控制私钥到节点解决重连。

### 4. 接管和确认

- 默认保留管理域名；域名/IP变更时显式检查 TLS SAN、Origin、节点地址白名单及财务插件连接地址。只改资源连接配置，不修改金额、支付、币种或历史快照。
- 启动目标只读检查，验证数据库、HTTPS、管理员登录、节点 mTLS 与现有资源投影；按原任务 ID 查询未知结果，不重新开通。
- 必须证明源不能继续派发，才能逐步解除目标维护。真实节点确认不足则停在“待节点核验”，不能标记“迁移完成”。
- 完成后源主机保留退役标记和回退材料，不自动删库、删证书或抹盘。后台显示实际阶段、失败原因和操作 ID，不造进度百分比。

### 5. 回退与恢复

- 目标尚未接纳新写入时，先隔离目标，再恢复原主控；不能双边同时解除维护。
- 目标已产生新写入后，不允许恢复旧备份覆盖新状态。必须用新源状态执行反向受控迁移或进入人工恢复；“回滚程序”不能当“回滚数据”。
- 每阶段先持久化 journal，再做副作用；断网、丢响应、重启只能继续原 operation ID。备份/解密/迁移/健康检查失败保留证据，不给无条件重试按钮。

## 后台与权限

系统管理提供“备份与迁移”：预检查、导出记录、上传/校验、恢复计划、阶段详情、取消条件与回退说明。上传只做验证，不立即停止服务或覆盖数据库；恢复执行需要管理员新鲜会话、重新认证、独立迁移权限与明确计划确认。API 不执行 root shell，不接收任意主机路径/URL，使用与内置升级共用的受限本机操作服务。

移动端单列步骤、长名称换行、固定但不遮挡内容的操作栏；危险按钮不抢默认焦点，Esc/焦点返回/键盘、浅深色、中英文本、loading/error/未知状态完整覆盖。完整私密包下载不能经公开静态目录；普通操作员和资源插件看不到导出材料。

## 实施与验收顺序

| 阶段 | 交付 | 必须验证 |
| --- | --- | --- |
| I01 | 一个入口、两种角色、旧入口兼容 | 真实 tty 选择/取消/EOF；Ubuntu22/24 × 两角色实际下载验签与生产 plan；无 apply/start |
| I02 | 新仓库签名发行与统一命令 | 实际匿名下载；固定 source/workflow/repository ID；只对新 Release 发布，不覆盖旧资产 |
| M01 | 源端停写/排空/隔离回执 | 实库并发、源服务/定时器停用、重启仍隔离、未知任务保留、不能同时派发 |
| M02 | 加密导出、清单和完整性 | 真 MySQL 导出/恢复；错密钥/篡改/截断/超限/路径/符号链接拒绝；秘密不入日志 |
| M03 | 空目标恢复及同身份只读检查 | 两台隔离22/24实例交叉恢复；schema/来源/身份/会话/权限/节点指纹与财务引用不变 |
| M04 | 接管、地址切换与回退 | 原 ID 重入、断电阶段、丢响应、双活防护、目标有新写入时禁止旧快照覆盖 |
| M05 | 后台完整闭环 | 实库 HTTPS 浏览器、权限撤销/CSRF/重新认证、手机桌面截图、真实下载上传与失败恢复 |
| M06 | 跨主控实例移交 | 独立源/目标身份、一次性短期配对码、磁盘/网络/IP/NAT映射、取消与所有权切换 |

沿用已约定的公开 CLI、API、真实服务/数据库与浏览器测试边界；不能用纯状态模型测试替代实际停止/导出/恢复。真 KVM、物理网络以及客户 VM 不停机连续性按用户决定后置并明确列出。当前 I01 实施中；I02 与 M01–M06 未完成。
