# 主控迁移：配置计划、发布与验证启动合同

这是 `M03 → M04` 的实现约束。已接入只读配置计划；正式发布、验证启动和接管尚未实现。前置条件是目标专用库、完整导入证明、运行材料和旧会话撤销均已通过实际回读；财务数据库、金额、支付与历史快照不参与。

## 已检查的现状与不能跳过的边界

- 当前 `PlanTarget` 和已安装协调器均要求 `/etc/aster-controller`、主控 unit、心跳 unit 不存在。直接复制配置到 `/etc` 会使后续核验全部拒绝，不能靠删除这条保护解决。
- `target-restore.json` 绑定原配置摘要和目标计划；材料重定位后的候选配置摘要不同。原封存不能改写为新摘要，也不能删除封存让服务启动。
- 私有 `runtime/config.json` 已保留原 controller ID、节点 profile 和资源映射，只改变实际材料位置及目标 DSN。它目前不是正式配置。
- `console_origin` 是服务启动参数，不在 `control.Config` 内。新导出已加入原 unit 的只读证据和离线验证；旧备份仍可能没有该证据。因此不能从监听 IP 猜管理域名；取得原值也不等于完成目标入口恢复。
- 现有原生主控 unit 仍以 root 运行。配置发布不等于完成控制面非 root 化；受限宿主操作服务和最小读取身份仍归 W13，不能把模板注释当隔离实现。

## 用户流程

### 管理入口的认证来源

测试沿用已确认的公开 CLI、实际加密归档及原生安装边界。新增导出保存
`source/controller.service`：只从本次隔离操作留下的固定原 unit 位置读取，
绑定原计划的文件摘要和 inode；不接受请求提供的路径。目标端只将其作为
加密备份中的数据，验证已管理的完整 unit 模板、原安装版本和启动参数，
提取 HTTPS Origin，绝不执行或安装原 unit。

`migration-validate-source` 的 `console_entrypoint` 为 `null` 表示旧备份缺少证据；
对象中的 `enabled=false` 才表示已经验证原服务没有开启控制台。两者不可混用。
域名证据不表示目标证书仍有效、DNS 已迁移、TLS 已批准或迁移已完成。
此变更不修改归档协议版本；旧验证器对不认识的可选文件会明确拒绝，必须使用支持
该文件的新验证器，不能删掉文件再包装归档绕过检查。

源入口证据与只读配置计划分别验收；可解析原 unit 不代表可发布或启动目标。旧包未知、
明确 API-only、摘要不匹配、版本/路径/沙箱变更、追加启动命令、非法 Origin 和大小边界均有
公开归档回归。原生 systemd 导出门比对实际安装域名和原 unit 摘要，必须使用对应源码结果。

### 已实现的只读目标配置计划

固定安装协调器增加 `target-configuration-plan --operation <原操作ID>`，Go 入口为
`migration-target-configuration-plan -operation <原操作ID>`；两者均不接收自由路径、
DSN、SQL、shell、额外证书参数或跳过核验开关。直接 Go 调用不替代协调器的宿主对象盘点。

root 在原操作目录 `/var/lib/aster-controller-restore/<原操作ID>/` 准备
`configuration-request.json`（root 独占、0600、普通单链接文件），字段精确为：

```json
{
  "schema": 1,
  "operation_id": "原32位操作ID",
  "target_plan_sha256": "database-plan.json中的原64位目标计划摘要",
  "console_enabled": true,
  "console_origin": "https://cloud.example.com",
  "listen": "127.0.0.1:9443",
  "tls_mode": "replacement"
}
```

这是字段示例，不可原样执行。Origin 和监听地址由本次实际入口部署决定；不从源监听地址推导。
- `console_enabled=false` 时 Origin 必须为空；旧包的源入口 `null` 不代替明确决定。
- `listen` 必须为规范的字面 IP 加固定非零端口，支持 IPv4/IPv6，不接受域名、zone 或组播地址。
- `tls_mode=replacement` 只读取同一操作目录的 `configuration-tls.crt` 和
  `configuration-tls.key`，均为 root 独占0600、单链接文件；不跟随自定义路径。
- `tls_mode=source` 使用认证备份中原证书，若仍留有 replacement 文件则拒绝，避免误用旧证书。
- 真正解析证书/私钥并核对配对、完整 PEM、链签名、服务端用途、SAN 和至少24小时剩余有效期。
  不接受前置垃圾、错私钥或过期证书；这不证明浏览器信任、DNS 或入口可达。

调用先核对原封存、专用数据库所有权、完整会话撤销后像、原撤销意图与材料字节。
输出绑定源配置/归档清单、目标计划、材料清单、会话意图、请求与4个候选文件摘要；
不输出 token、DSN、私钥或会话。它只在内存推导配置，不创建 `/etc/aster-controller`、
发布意图、批准文件或 systemd unit，明确 `configuration_published=false`、`migration_ready=false`。
重复计划仍重新核验当前输入和真实 SQL，不以历史成功记录替代；原封存始终保留。

Ubuntu22/24 原生门新增实际 openssl 证书、真实 SQL 只读重入、证书漂移和新增会话拒绝。
报告新增4项计划证据，汇总器与工作流均强制要求，但不据此声称配置已发布或登录已验证。

### 原生耗时与认证边界

`f6e467b` 的 CI 40684247060 终态为13/14：Ubuntu22原生恢复通过，Ubuntu24在3600秒
来宾预算耗尽，最后记录位于数据拒绝阶段，没有最终来宾成功报告。本轮将同一次 root 操作
中的两次归档解密收敛为一次认证能力生命周期；原目标计划、封存锁内的来源语义和密文字节
检查仍保留，操作之间不缓存、不重试、不降低加密强度、不延长验收预算。性能改善须由
后继源码的两套原生测试证明，不能用本地计划测试绿代替。

1. 显示原控制身份、目标主机、数据库和恢复操作编号；只显示批准摘要，不回显 token、私钥、DSN 或会话值。
2. 核对管理域名、目标监听地址和 HTTPS 证书。默认保留**可认证的原值**；旧包没有 Origin 证据时，明确要求独立 root 批准，不推测、不静默关闭控制台。
3. 展示“配置已恢复，尚未接管”。发布配置不启动服务、不启动心跳、不向节点派发、不修改财务插件连接。
4. 后续单独进入“验证登录与连接”，最后才是“接管”。不能用一个成功提示覆盖这三个不同阶段。

## 受控发布

- 使用固定安装入口和原 operation ID。API 只提交结构化批准，不提供任意目标路径、unit 文本、shell、下载 URL、SQL 或 `force`。
- 不可变发布意图绑定源归档、目标计划、材料清单、会话撤销意图、目标配置规范摘要以及明确批准的 Origin/TLS/监听调整。
- 在安装锁和目标封存锁内，重新验证已安装程序、原封存、完整数据库后像、材料字节和发布批准。权限、数据库/证书漂移或外来 unit 一律拒绝。
- 固定 `/etc` 同文件系统私有暂存目录，文件独占创建、验证、fsync；以 `RENAME_NOREPLACE` 原子发布完整配置目录。不得覆盖现有目录、链接、半成品或第三方配置。
- 完整发布后回读目录、文件权限/链接数、内容和绑定。既有目标操作只有在能从认证来源重新推导出相同发布结果时，才可接受这个已发布目录；不能仅信目录中的自报 manifest。
- 保留原 target seal、源配置摘要和原材料清单，追加独立发布证明。未安装或启用服务的阶段，systemd unit 仍必须不存在。

## 中断与重入

- 普通重入只核验完整结果，不重写、不补文件、不轮换凭据。rename 成功但返回丢失时，只读核对精确结果。
- 发布意图存在而未完成：普通状态不得报告完成。显式恢复只可继续同一意图、同一固定暂存目录，逐项接受完全匹配的已写文件并独占补齐缺失项；部分写入、额外文件或内容改变不得自动修复。
- 配置不存在但存在外来暂存目录、意图缺失/损坏、源/目标身份不符均保留证据并拒绝。不得删除 journal 然后换操作编号重试。
- 无论哪种发布故障，源不得解除隔离，目标普通 `serve`/心跳/资源写仍被封存拒绝。

## 验证启动与真正接管是后续独立授权

验证服务只允许明确批准的 HTTPS 入口、重新登录和只读资源核验；现有旧 Cookie 必须拒绝。由于重新登录本身会产生新会话与审计，它必须有新的、可审计的数据库阶段合同，不能继续冒充“精确等于撤销后的零会话库”。

不得为了浏览器测试放行现有普通 `serve`：它包含资源写、后台执行器和心跳。验证模式必须在后端逐类拒绝业务写，且持有独立的受限启动许可。API/Web 进程不能自行解除宿主封存。验证重启、并发旧进程、地址不匹配、退出和许可撤销均属于软件验收。

源持久隔离、节点单活确认、财务资源连接地址调整和回退条件全部满足后，才能进入真正接管。目标产生新业务写入后，不允许旧快照回滚覆盖它。真 KVM 后置不免除这些软件门槛。
