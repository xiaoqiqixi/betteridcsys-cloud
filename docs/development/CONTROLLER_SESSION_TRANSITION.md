# 主控迁移：旧会话撤销合同（开发中）

本阶段紧接目标数据回读与私有材料恢复。不是财务会话迁移，不改用户密码、角色、授权修订、资源任务或金额/支付/历史快照。

## 必须改变与必须不变

- 源包中的 `controller_console_sessions` 包含已登录及匿名会话；目标激活前全部撤销，旧 Cookie 不得继续使用。新主控要求重新登录。
- 保留 `controller_console_users` 的密码哈希、权限、启停和修订，保留登录限流及历史身份操作。不能通过重置用户或提升权限解决迁移登录。
- 节点 mTLS 身份与 Web 会话分离。删除会话不轮换节点证书，不改变节点端点、允许地址或历史 profile 摘要。
- 身份审计只允许追加一条由本操作绑定的会话撤销事件。不得修改/删除原审计，不在事件中写 Cookie、token hash、密码或 DSN。

## 一次明确的事务转换

1. 继续要求 root 可见库存/授权检查、同一目标封存、完整数据与材料回读。只受管理的本操作专用库可以执行。
2. fsync 不可覆盖的撤销意图：绑定源包、目标计划/数据库身份/结构证明/材料清单、源会话数量、源审计下一 ID，以及固定事件时间和操作 ID。不得接受任意 SQL 或表名。
3. 在专用事务和既有身份锁下，先重新核对原数据库的完整前像，再删除全部旧会话并插入固定事件。事务提交前核对精确后像；失败回滚，不保留部分撤销或重复审计。
4. 审计 ID 必须由预先核对的源 auto-increment 高水位确定，检查范围及占用；不得用重试新分配 ID 掩盖未知结果。
5. 撤销后核验不是跳过会话表：会话表的结构/编码保持不变且记录数必须精确为零；审计表必须等于源记录加唯一计划事件及明确的高水位变化。所有其他表仍与认证源逐字节一致。

## 重入、结果不明与后续阶段

提交响应丢失后先走只读状态核验。完整后像才能报告撤销完成；仍是完整前像、部分状态、重复事件、外来变化或缺失证明都不能当成功。不得自动重新导入源包以“恢复校验”。

需要显式、受限的同操作恢复路径：只有原意图不变、精确前像仍成立、没有计划审计事件且源/目标仍隔离时，才可继续原事务。既不是换 operation ID，也不是删除 journal 再试；混合状态须保留证据并拒绝。

MySQL 的自增计数器不随事务回滚还原，见 [InnoDB AUTO_INCREMENT](https://dev.mysql.com/doc/refman/8.0/en/innodb-auto-increment-handling.html)。因此还定义一个严格的中间态：所有原记录保持不变、计划事件不存在，只有身份审计表的计数器恰好从预定 ID 前进一次。只有显式 `target-session-resume` 才能接受这一中间态，仍使用原事件 ID，不执行 `ALTER TABLE`、重新分配 ID 或降低计数器。额外行、其他计数变化、表结构变化一律拒绝。

后续材料状态、配置发布与接管必须选择已批准的数据库阶段核验：导入前像或会话撤销后像。不能继续用“原始库完全相同”假装撤销后的库未改变，也不能通过忽略两张表放宽所有核验。最终程序启动/节点单活仍由接管阶段单独授权。

## 验收

- 真 MySQL：包含已登录和匿名会话；账户/角色/密码/资源/限流原样保留，源库不变。
- 事务失败回滚、提交丢响应只读确认、再次调用不新增审计、缺失/篡改意图和额外会话/审计拒绝；不能把 SQL/网络异常算拒绝成功。
- 既有结构、外键、自增高水位与目标 ownership 核验继续执行。
- 实际 HTTPS 服务恢复后：旧登录与匿名 Cookie 均失效；原密码可重新登录；旧权限被后端重新确认。不得用数据库行数代替浏览器身份验收。
- 控制面仍封存直到下一阶段批准。真 KVM/物理网络后置不免除本阶段实库、实际进程和浏览器验收。

## 当前实现范围

- 固定安装入口增加 `target-revoke-sessions`、`target-session-status`、`target-session-resume`，均只接受原 operation ID；不接受 DSN、任意路径、时间、SQL 或 force。
- root 协调器核查宿主未激活、封存、全局数据库对象与授权；Go 在同一封存锁内复核完整导入证明、材料字节及清单。`sessions-started.json` 独占写入并 fsync 后才开始事务。
- 会话撤销和唯一审计在同一事务执行。34 张表、ownership、外键/索引/编码及自增状态全部核对；不是忽略会话表和审计表。审计动作固定为 `migration.sessions_revoked`，不含会话值或秘密。
- 普通重复调用只读确认最终状态。未提交的前像和回滚计数中间态不能伪报成功，也不会自动再执行；恢复必须显式选择同一操作。
- 材料状态入口在撤销后改为精确核验批准的后像。原 `target-data-status` 仍只验证原始导入前像，撤销后应使用 `target-session-status`，不能声称原库完全未变。
- 实库测试新增已登录/匿名会话、保留历史审计及删除高 ID、回滚计数、绑定篡改、重复事件、额外会话、密码/资源行和外键变化拒绝、源库不变。原生夹具新增真实只读 SQL 拒绝、显式恢复、只读重入、材料阶段联动及仍然封存。

上述实库和原生新增用例尚待本次源码 CI 实际运行。本机无本轮隔离 MySQL，编译或本地 race 通过不等于 SQL 验收。配置发布、实际 HTTPS 旧 Cookie 失效/重新登录、源退役和节点接管仍未完成；当前输出明确 `target_activation_approved=false`、`migration_ready=false`，原生报告明确 `session_browser_verified=false`。
