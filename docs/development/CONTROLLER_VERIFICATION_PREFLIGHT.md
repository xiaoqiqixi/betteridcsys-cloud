# 迁移验证的运行前检查

## 用途

`target-verification-runtime-check --operation <原操作 ID>` 检查已停止的验证环境能否继续使用**同一个**认证数据阶段。它只做检查，不启动服务，也不生成可供之后复用的运行许可。

初次创建验证 SQL 账号时，`verification-credential-check` 仍要求完整的原始零会话数据像。验证登录发生后，应检查原阶段允许的认证变化，而不是放宽这个旧入口或把当前数据库重新当成基线。

## 检查顺序

1. 原生管理入口持有安装锁和目标锁，核对固定安装产物、目标输入、系统服务及进程清单；运行中的控制进程不能通过。
2. Go 在原归档和目标封存控制锁内核对完整阶段：业务表和历史审计保持原样，新增会话、限流记录和认证审计必须符合原阶段规则。
3. root 独立核对原三账号清单、账号身份、最小授权和完成回执。只读检查不得创建账号、补授权、解锁或改密码。
4. Go 再次核对完整阶段及其原始批准期限，真实使用保存的最小权限凭据连接 MySQL，验证当前 SQL 身份、授权及数据库归属。任何已经开始的撤销都拒绝继续。
5. root 复核账号回执和停止状态。输出不含 DSN、密码、TLS 私钥或恢复密钥，`service_started` 与 `migration_ready` 始终为 `false`。

没有原阶段、业务数据变化、批准或回执变化、期限失效、账号变化、撤销开始及未知进程均拒绝，不自动重试、不续期、不重建意图。`verification-data-status` 则保留撤销后的只读核验能力，不尝试登录被锁定的账号。

## 验证与边界

公开 CLI 合同覆盖命令清单、禁止路径/凭据/期限覆盖和错误脱敏。原生 Ubuntu22/24 场景增加了真实最小权限 SQL 认证变化后的检查、重复检查不改意图、旧凭据入口仍然拒绝变化后的数据像、业务/批准变更拒绝、数据库强制只读下检查，以及撤销后拒绝继续。

这些新增原生断言必须由本次源码自己的 CI 执行；旧提交的通过结果不能作为它们的证据。本地 macOS 的编译、静态检查和 MySQL 回归也不能代替 root/systemd 原生验收。

2026-10-30 本地 macOS arm64/MySQL8.4.13 完整 race 回归实际执行 531 个顶级测试，0 运行时 SKIP，耗时 597.763 秒；5 项 Linux/root 专属测试明确留在原生入口。公开 CLI 合同 9、原生/工作流合同 70、安装单测 19、安装合同 111、包合同 26 通过，Go vet、4 个 Linux amd64 构建及启用 ShellCheck 的共用工作流检查通过。独立测试库正常关闭，测试账号、私有数据与凭据清理完成，系统服务和证书信任未改变。这些是本地证据，不是新增运行前检查已获原生验收的声明。

后续实际启动器必须在取得父子独立运行锁时重新执行完整授权，不能采信先前保存的检查 JSON；还需完成非 root 子进程、有限期控制通道、父进程死亡保护、HTTP 只读页面、真实退出及 SQL 连接排空。此命令不解除目标封存，不接管节点，不变更财务金额、支付或历史快照。
