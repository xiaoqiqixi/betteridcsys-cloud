# 迁移验证期间的数据边界

这是主控迁移协调器的数据核验协议，不是新的迁移启动命令。验证 HTTP 处理器、宿主许可、运行进程、停止排空和正式接管分别验收；数据报告不能代替其中任何一步。

## 为什么需要独立阶段

恢复并撤销旧会话后，数据库有一个精确、可核验的后像。管理员重新登录会产生新会话、登录限流记录和身份审计，因此运行期间不能继续声称数据库与该后像逐字节相同，也不能直接忽略这三张表。

`Archive.PlanVerificationDataPhase` 只接受原会话撤销后像，绑定原恢复所有权、会话撤销意图、验证计划摘要、账号完成回执摘要及明确的 UTC 有效区间。区间必须使用微秒精度、起点不早于会话撤销、长度不超过一小时。协调器必须在开放登录前持久保存这些字节，不能事后把变化的数据重新认作基线。

`Archive.VerifyVerificationDataPhase` 重建并逐字节比较该意图，然后通过同一个只读事务核验完整数据库。它继续要求原绑定的迁移 SQL 身份；有 SELECT 权限的其他账号也不能替代。受限登录账号与数据核验账号不是同一职责。

## 可以变化的内容

| 表 | 允许的变化 | 必须保留的约束 |
| --- | --- | --- |
| `controller_console_sessions` | 验证区间内创建、正常删除的新会话 | 原归档的匿名或登录 Cookie 哈希不得重用；用户须在原库中启用；匿名会话恰好十分钟，登录会话五分钟至二十四小时，与现有身份服务一致 |
| `controller_console_login_limits` | 原十五分钟窗口正常累加、窗口到期后的重置、新桶和二十四小时后的清理 | 未过期的原窗口不能降低次数、提前重置或删除；新/变化次数为 1–4096；新时间在批准区间内；原样记录保持原字节 |
| `controller_identity_audit` | 区间内追加 `identity.login`、`identity.logout`、`identity.login_failed` | 原历史记录和会话撤销事件逐字节保留；身份、目标和时间形状受限；旧编号不得回填；真实事务回滚造成的自增编号间隙可以保留 |

所有其他表、账号资料、密码、权限、资源任务及 DDL 必须与原后像一致。认证表本身的列、外键和其他结构也不能改变。审计表唯一可变的 DDL 部分是经校验的自增高水位。历史审计编号覆盖完整的有符号 BIGINT 范围，不以零或最小整数充当“尚未读到记录”的哨兵。

## 核验与报告

- 数据和元数据由原快照边界读取；每张认证表都逐条解析，不是从摘要中删除三张表。
- 历史审计前缀流式比较，报告不返回原账号、令牌、数据库凭据或审计内容。
- 单条记录与索引内存有独立上限，超限明确拒绝，不截断、跳页或放宽核验。这个资源预算不是变更次数或产品功能上限。
- 成功只表示当前数据满足本阶段合同。`migration_ready` 与 `target_activation_approved` 始终为 false。
- 形状核验不能证明写入来源。协调器仍须独立核对 SQL 最小权限、对象库存、宿主批准和原封存，并在最终核验前停止登录、排空连接。不得边运行边凭一次数据报告宣布迁移完成。

## 测试与接入边界

使用已确认的加密归档公开 API 和真实隔离 MySQL：原历史字节、最小 BIGINT、原 Cookie 重用、停用账号、会话时效、限流窗口累加/重置/清理、审批绑定、审计篡改、业务/密码/权限变化、外键/额外表/触发器，以及其他 SQL 身份均有明确用例。每个故障后恢复测试夹具，再要求合法状态核验成功，避免数据库断线冒充拒绝。

SELECT-only 账号的实际写入探针须收到 MySQL 1142，随后数据核验仍因原身份绑定而拒绝；不能为了让这个账号通过而删除 CURRENT_USER 检查。测试使用的合成认证记录不是浏览器登录证据。

尚须接入：不可变宿主批准、非特权验证服务、有效期与重启规则、停止/排空及账号撤销的数据阶段分支、真实源归档的新登录浏览器流程。正式接管还需要源隔离、节点单活、财务重连与回退合同。现有账号准备/撤销的原生证据不能替代这些后续验收。
