# 迁移验证服务的运行生命周期

`control.ServeVerificationConsole` 是受限 HTTPS 服务组件，不是迁移宿主的启动许可。当前尚未接入非特权子进程、root 协调器和 systemd；不能直接调用普通 `serve` 来替代这些步骤。

## 输入与权限

- 接收已绑定的监听器、独占的最小权限 SQL 连接池、只读配置、原操作标识、TLS 证书及到期时间；不接收财务 token、节点私钥内容或迁移 SQL 凭据。
- 重新检查实际 SQL 身份和完整最小授权，再构造既有 `NewVerificationConsole`。没有管理员 bootstrap、资源执行器、overlay runner、心跳或节点远程查询。
- 实际监听地址必须等于已批准配置。证书必须匹配固定 HTTPS Origin，具有服务器用途，当前有效且覆盖整个剩余许可期。只启用 TLS 1.2 及以上；真实 HTTP/1.1 与 HTTP/2 均回归。
- 到期时间使用 UTC 微秒精度，必须尚未到期且剩余时间不超过一小时。不接受身份时钟覆盖函数，不能由请求或运行参数延长许可。
- 宿主仍须独立认证原归档、完整数据阶段、TLS 发布和不可变批准，验证证书链及专用账号库存。这些不是本组件单凭参数能够证明的事实。

## 停止行为

停止信号通过调用上下文传递；绝对期限也绑定到所有 HTTP 请求的上下文。每次请求再次检查许可，停止时先封闭新请求入口，再取消正在进行的认证事务、关闭监听和连接，等待已接纳的处理器退出，最后关闭独占 SQL 池。处理器等待有固定上限，未退出返回失败，不报告“排空成功”。组件在初始化失败时也关闭交给它的监听器和 SQL 池，调用方不得与其他服务共享这两个对象。

关闭客户端、`http.Server.Close`、SQL 池关闭和函数返回都不等于 MySQL 服务端已没有连接。受阻的 MySQL 查询可能在客户端取消后暂时继续存在；原有受限连接的两秒 InnoDB 锁等待限制仍保留。root 协调器必须另行确认实际子进程退出、宿主运行锁和真实 MySQL 连接清单，然后才能完成数据核验或账号撤销。

匿名认证在等待身份锁前，已经提交全局与来源 IP 的限流预留。取消请求不能把这次尝试退还，否则客户端可以利用主动断开规避限流。回归测试明确要求这两个准确桶、次数、时间和原 DDL，随后停止前后完整 SQL 后像一致；不把整张限流表从核验中排除，也不改变原身份逻辑来迎合错误的“失败请求从不写数据”假设。

## 已覆盖的组件验收

沿用已确认的公开 HTTP/TLS 和真实隔离 MySQL 边界，不替换身份、SQL 或自己的服务实现：

1. 原账号真实登录、读取验证状态；管理员业务写仍明确收到 HTTP 403。
2. 停止后监听器与独占池关闭，另从 MySQL 服务端观察该专用账号连接归零。
3. 真实到期自动退出，后续请求不能重新生成会话。
4. 先观察到实际 InnoDB 身份锁等待，再停止服务；请求不成功、命名锁和连接最终释放、没有新会话或越界数据变化。
5. 错误 Origin 证书、过期/未来/过短证书、客户端专用证书、无效许可区间或精度、时钟覆盖与监听漂移在服务接纳前拒绝。

## 下一接入边界

受信 root 进程必须在原封存和安装约束内准备一次性、有界的私有控制通道，向独立非 root 子进程只传最小 SQL 凭据与服务 TLS 材料。子进程不得持有原归档恢复密钥、迁移账号、财务 token 或节点客户端私钥。父子身份、无附加组/能力、禁止获得新权限、固定二进制、批准期限及真实退出均须在 Ubuntu22/24 检验。

宿主运行锁要覆盖实际进程生命周期，而不是 HTTP 函数生命周期。父子不能只依赖同一 open-file-description 的 `flock` 副本；父进程必须保留独立守护，子进程退出前也不能出现“看似已排空”的空档。父退出、期限届满、显式停止、重复启动及原批准内的明确恢复分别处理，不自动续期、重建意图或解除目标 seal。

最后才能接入原账号新登录的迁移页面、手机/桌面浏览器、停止后的数据证明，以及正式单活接管与回退。当前组件不代表这些功能已经完成。
