# 安装云主控与 KVM 被控

[返回首页与安装命令](../README.md#一键安装) · [首次使用](../aster-cloud/docs/GETTING_STARTED.md)

主控、被控各使用首页对应的一条命令。命令会下载已发布版本、校验来源，再进入配置向导；不需要下载源码、安装编译器或手动构建。

当前下载版本为 **0.1.0-rc.1 预发布版**。真实 KVM、物理网络与生产容量尚未验收，请先用于独立测试环境。

## 安装前准备

| 项目 | 主控 | KVM 被控 |
| --- | --- | --- |
| 系统 | Ubuntu22.04/24.04 amd64，systemd | Ubuntu22.04/24.04 amd64，systemd |
| 基础工具 | Python3.10+、curl、系统 CA、sudo/root 权限及交互终端 | 同左 |
| 服务器 | 独立管理服务器和专用数据库，不复用财务库 | 专用计算宿主，可用的 `/dev/kvm`，至少2GiB内存及足够磁盘 |
| 身份与证书 | 管理地址、有效 TLS 证书/私钥、信任 CA、管理员邮箱 | 节点/机房/分组 ID、节点证书、主控信任 CA 与已审核客户端指纹 |
| 镜像 | 无需准备客户镜像 | 已批准的平面 qcow2 镜像与完整 SHA256，位于 `/var/lib/aster-images` |

TLS、DNS 和网络规划需由你确定。安装器不会关闭证书校验、擅自开放防火墙或修改物理上联；目前不自动申请公共证书。

## 主控安装

1. 运行首页“安装主控”命令，等待官方文件下载和验签。
2. 确认基础依赖安装时输入 `apt`。在干净专用服务器上，依赖由安装器按固定列表准备。
3. 配置选择处留空进入向导，不需要手写 JSON；`software` 只安装程序，不能作为可登录站点。
4. 输入 HTTPS 管理地址、证书、私钥、信任 CA 和监听地址。若选择对外监听，需明确确认 `expose`；防火墙仍由你管理。
5. 数据库处选择 `new`，再确认 `provision`，创建新的专用数据库与独立的运行/迁移账号；也可使用符合权限要求的既有专用数据库。
6. 输入首个管理员邮箱。密码在初始化时私密输入，不出现在命令行或日志中。
7. 核对计划后输入 `install`，需要启动时再输入 `start`。安装器完成配置、数据库检查/迁移、管理员初始化、systemd 启动和 HTTPS 健康检查。

**完成标准：**结果为 `service-ready`，使用自己配置的 HTTPS 地址和管理员账户登录。下载完成、文件安装成功或只读计划通过，都不是站点已经可用。

## 被控安装

1. 在专用 KVM 宿主运行首页“安装 KVM 被控”命令。
2. 按需要确认 `apt` 与 `libvirt`，自动准备官方 libvirt/QEMU 软件栈；已有活动 libvirt 不被接管或重启。
3. 配置处留空，填写节点服务地址、证书与节点/机房/分组 ID，确认 `dedicated-kvm`。
4. 输入主控信任 CA、已审核客户端指纹、镜像路径/摘要，以及 CPU、内存、磁盘分配上限。不要将主控客户端私钥复制到被控。
5. 核对计划后确认 `install` 和 `start`。初始节点处于维护模式，网络、删除和存储迁移能力默认关闭。
6. 回到主控完成节点准入与检查，再按需要开放相应操作权限。

**完成标准：**本机服务启动后还要通过主控的认证与准入。`libvirt-prepared` 仅表示依赖软件准备完成；`node_started_pending_controller` 表示等待主控确认，不能据此认定虚拟机已可创建。

## 失败与恢复

- 下载或验签失败：停止安装，检查网络和版本来源；不要替换成未核验文件或跳过 TLS。
- 输入不完整或不确认：不默认同意安装。可以先查看计划，准备好实际配置后再继续。
- 出现已有下载目录或中断回执：保留原目录，核对原版本和操作记录；按[详细恢复说明](../aster-cloud/deploy/install/README.md)明确使用同一次操作的 `--resume`，不要删除状态后重跑。
- 启动失败：查看原安装回执和对应 systemd 日志；不能把 `software-only` 或本机监听当成管理员登录成功。
